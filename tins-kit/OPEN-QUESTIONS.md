# OPEN QUESTIONS — what this work could not resolve, and who or what could

| ID | Question | Why it is open | Who/what can resolve it |
|---|---|---|---|
| Q-1 | Does the entry path work for a **different model family** (GPT, Gemini, Llama, Qwen) and a **different agentic harness** (Codex CLI, Gemini CLI, opencode, Cline, aider)? | Only Claude models were available (Haiku 4.5 and Sonnet 5.5; BENCH.md). The tool-less relay is a different harness *shape*, not a different family | Anyone with another CLI agent: add one line to `bench/agents.json` and run `node bench/run.mjs --agent <name> --conditions kit,kit-nowrap,bare` |
| Q-2 | Does anything break on **native Windows** or across **WSL ↔ Windows**? | Not available. Known risks: absolute worktree pointers (RF-12), `shell: true` gate commands under `cmd.exe`, `fsync` on directories (skipped on win32 by design, untested), SIGKILL-based test (skipped on win32) | A Windows machine: `node test\run.mjs`, then `kit new`, `kit task new`, `kit merge` from PowerShell and from WSL on the same repo |
| Q-3 | Is the `--why` escape abused? | RD-20 makes code-only sessions state a reason, but cannot judge it | Review a sample of `spec_waiver` reasons across real projects; if abused, require the waiver at task level (`tasks/<id>.md`), set by the planner, not the agent |
| Q-4 | Node 18 / 20 compatibility | Only Node 22.22.0 was available. Risky spots: `fetch` in the web template test (Node 18 global fetch), `node --test` discovery rules, `fs.cpSync` in tests | CI with Node 18 and 20 |
| Q-5 | git version floor | `%(trailers:only,unfold)` and `interpret-trailers --if-exists` are believed to need git ≥ 2.22 (INFERRED from release notes). Only git 2.43 was run | Run the self-test with git 2.22–2.30 |
| Q-6 | Are retrieval labels biased? | One labeller; the labeller and the retriever share a model family; 16 fragments | A second, human labeller on a fresh fragment set, and a non-Claude model for the "reads index" method |
| Q-7 | Does the injection canary discriminate for stronger injections or weaker models? | Haiku and Sonnet ignored both the HTML-comment injection and the plausible "action item" injection in every run, bare included (BENCH.md). The code-enforced containment was exercised only by the `obeys-injection` calibration agent | Harder canaries (an injection inside tool output, an injection that matches the task's goal) and weaker models |
| Q-8 | What happens with **concurrent LLM agents**, not scripted ones? | The two-worktree test ran scripted agents concurrently; LLM bench runs were sequential | Run two `kit run --task …` with real agents in parallel worktrees; expect the same behaviour, since nothing in the kit is shared between worktrees except git's own locking |
| Q-9 | Is the incumbent really as the brief describes? | No read access to the fork; COMPARE.md could not be written | The owner: diff COMPAT.md "Preserved" columns against the real files |
| Q-10 | Does regeneration from SPEC alone reproduce behaviour? | The bench tasks are incremental edits, not from-scratch regeneration | A bench task "delete src/, regenerate from SPEC.md, run the hidden acceptance tests", repeated N times per model |
